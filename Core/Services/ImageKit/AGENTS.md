# ImageKit

**Purpose:** Photos, their clips and their placeholders: ThumbHash decoding, the URLs of sized variants, the one configured Nuke pipeline, the clip cache, and prefetching both.
**Tier:** Services
**Project deps:** none (packages: `FactoryKit`, `Nuke`)
**Public Factory keys:** `imagePipeline`, `imageCaches`, `clipCache`, `photoURLBuilder`, `thumbHashRenderer` (all `.singleton`)
**Entry points:**
- `ThumbHash` — decoder (checked against the reference implementation's output) and average colour.
- `ThumbHashRenderer` — actor: base64 ThumbHash → `UIImage`, decoded once and kept in an `NSCache` (500, fewer under memory pressure); `averageColor(base64:)` for tints.
- `PhotoURLBuilder` + `PhotoSize` — the variant URL for a photo key at a fixed size bucket: `https://images.openskatemap.app/cdn-cgi/image/width=…,fit=…,format=auto/<key>` (`URL.openSkateMapImages`, the R2 bucket's domain with Image Transformations). A `nil` base URL turns photo loading off, and every photo then renders as its ThumbHash. `clipURL(for:)` is a photo's clip straight from the bucket (`https://images.openskatemap.app/<key>`, progressive MP4), never through transformations.
- `ImageLoader` (`imageLoader`, `.onPreview { .placeholder }`) — images through the one pipeline (disk cache, memory caches), so features don't import Nuke. `image(_:_:)` resizes an image from outside our domain (YouTube thumbnails on spot videos); callers pass one fixed size per use (it's part of the cache key). `photo(_:_:)` loads one of our variants as the CDN sized it, the same request as `PhotoLoader` (collection covers in lists), so it shares the map's cache entries and isn't re-encoded.
- `ImagePipelines.make(caches:)` — one pipeline: decode queue width 3, the memory and disk caches of `ImageCaches` (`ImagePipelines.useCase`: pin, which every `.pin`-size request of ours is tagged with, so map thumbnails don't evict covers; photo for the rest; 400 MB on disk).
- `ImageCaches` — those caches, so they can be emptied: `removeAll()` runs when an account ends (the app's account-end handler), since a private spot's or collection's photos belong to the account that loaded them. Nuke's own `cache.removeAll()` would miss the per-use-case memory caches.
- `ClipCache` (`clipCache`) — actor: clips on disk, so a clip played once plays at once and offline after (cache-first, as every screen is). Whole files, no byte ranges (a clip is at most 16 s at about 1.8 Mbps, ~3.6 MB): `Caches/clips/<SHA-256 of the URL>.mp4`. One download per URL, whoever asked; it lands as `<hash>.part` and takes the clip's name in one rename, so a file under that name is always whole and a failed or cancelled download leaves nothing that looks complete (`sweep()` clears `.part` files a kill left). `beginPlaying(_:)` hands a player the file when it's there, dated now; otherwise it returns nil (the player streams) and downloads the clip at high priority alongside, or raises a prefetch already running, and a download a play started or joined always finishes, so the next play is local. The file isn't evicted until `endPlaying(_:)`. `prefetch(_:for:)` replaces one owner's wishes: low priority, never over an expensive or constrained network (`allowsExpensiveNetworkAccess` and `allowsConstrainedNetworkAccess` off; a play that joins such a download and loses it to that limit downloads again without it), and a prefetch nobody wants any more is cancelled unless a play joined it. `sweep()` (the app runs it at launch and on going to the background) removes the least recently played clips until the folder is under 300 MB, never one playing. `removeAll()` runs when an account ends, as `ImageCaches.removeAll()` does.
- `PhotoPrefetcher` — `@MainActor`, one per screen: what it shows next, each call replacing the last; `cancel()` or its going away stops everything. Photo variants go through Nuke's `ImagePrefetcher` (`ImageRequest.prefetchedPhoto`: the image id and use case of `PhotoLoader`'s request, so a load finds the prefetched image, under the same network limits as clips), clips through `ClipCache`, in the order they were asked for. Prefetch only what nothing loads yet: Nuke coalesces a load into a prefetch already running for the same URL, network limits and all.

**Ownership map:** decoded placeholders → `ThumbHashRenderer`; downloaded images → the pipeline's caches; clip files, their downloads and eviction → `ClipCache`.

## Rules

- One pipeline, wider queues; never a second pipeline built from the same `Configuration`.
- Request only `PhotoSize` buckets: sizes are part of every cache key.
- The ThumbHash shows until the variant arrives, and stays if it can't load: local `cf dev` photos live in a local R2, not on the image domain.
