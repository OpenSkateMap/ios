# OpenSkateMap iOS

The iPhone app for OpenSkateMap, an open, hand-curated map of skate spots. UIKit, iOS 26, local-first: the UI reads a local SQLite database and a sync layer fills it from the API.

## Conventions

- **Scroll views:** make every one with `.softEdges()` chained on (ComponentKit; lint `soft_scroll_edges`): iOS 27 draws hard edge effects under bars by default.
- **UI:** UIKit first; SwiftUI only in small leaf views. All layout with PinLayout in `layoutSubviews` / `viewDidLayoutSubviews`, sizing in `sizeThatFits(_:)`. No Auto Layout (lint `no_auto_layout`). Labels are ComponentKit's `Label`, measured with `TextLayout` (TextKit), never a bare `UILabel` (lint `uilabel_instance`). PinLayout chains follow its style guide: `[edges, anchors, relative].[width, height, size].[pinEdges()].[margins].[sizeToFit()]`, edges top, bottom, start, end; `mise run ios:format` puts them in that order (`ios:format-pinlayout`). A chain that is a statement keeps `.pin` on its first line and puts each call on a line of its own below it (`view.pin` / `.top()` / `.start()`), one call too (Ertem, 2026-10-20).
- **Right to left** (Arabic; Ertem, 2026-10-22): `AppDelegate` makes one launch call, ComponentKit's `UIView.followLayoutDirection()` (snapshot suites make it in `init()`), so `start`/`end`, `marginStart`/`marginEnd`, `before`/`after(of:)`, `edge.start`/`.end` and the Start/End anchors follow each view's own layout direction. `left`/`right` only where a placement is truly physical (the side a swipe goes, a zoomed photo, content inside a mirrored row, a field that reads left to right), between `// swiftlint:disable pinlayout_left_right - <reason>` and its `enable` (lint `pinlayout_left_right`). A frame computed by hand is measured from the leading edge and placed with PinLayout (`.top(y).start(x).width(w).height(h)`), never set directly (except Discover's beside-map panel, which follows the finger unrounded and mirrors its own x); a horizontally scrolling row lays out with ComponentKit's `layoutRow(_:spacing:insets:size:)`. A spot's photos page from the right, the next one coming from the left, as the system photo viewer does (Ertem, 2026-10-22); the photos themselves never flip. Handles, usernames and links run left to right (ComponentKit's `runsLeftToRight()`: Edit Profile's username and handles, Add Video's link, Add People's @username or email). Symbols that point use `.forward`/`.backward` names; whoever makes a text alignment glyph flips it (`imageFlippedForRightToLeftLayoutDirection()`); a picture of a real-world object (`photo.badge.plus`) never flips (HIG). Text stays `.natural`; text set against the trailing edge uses ComponentKit's `trailingTextAlignment` (a literal `.left` or `.right` is lint `pinlayout_left_right` too).
- **Safe area:** a screen's horizontal margins sit past the safe area (`view.safeAreaInsets`, or `view.layoutMargins`, which include it). Both are physical left and right: pass them whole to `start(_:)`, `end(_:)` or `horizontally(_:)`, which pick the side, and add the margin with `marginStart`/`marginEnd`/`marginHorizontal` (or build a `UIEdgeInsets` of both sides); never `start(insets.left + margin)`. In landscape iOS reports the sensor housing's inset on both sides, and a sheet in compact height spans the screen; a fixed inset puts content under the Dynamic Island (Ertem, 2026-10-19). Plain `UICollectionViewCell`s in a list add their own `safeAreaInsets`; list cells get it from the list. A scroll view that lays out its own margins sets `contentInsetAdjustmentBehavior = .never`.
- **Accessibility** (App Store accessibility labels, 2026-10-21; the default text size and settings look unchanged):
  - **Larger Text:** at accessibility sizes, a label that would cut its text short wraps (`Label.linesAtAccessibilitySizes`), and pieces sharing a line stack (a row's value under its title, button pairs at full width).
  - **Reduce Motion:** stops decorative motion (jiggle, bounces, pops, tilts) and lands map moves at once. Toasts and decided review cards fade.
  - **VoiceOver:** content a panel covers is hidden from VoiceOver. An editor's Escape runs its Cancel.
  - **Voice Control:** an element whose label adds more than its visible text gets that text as `accessibilityUserInputLabels`.
  - **Differentiate Without Color:** a state shown only by tint changes shape too.
- **State:** `@Observable` models. UIKit reads model state in `updateProperties()` (iOS 26 automatic observation tracking) and lays out in the layout callbacks. No Combine, no `@Published` (lint).
- **Dependencies:** FactoryKit registrations in `<Type>+Dependency.swift`. No Point-Free `@Dependency` outside the one sqlite-data bridge (lint).
- **Services:** Sessions are `@MainActor @Observable` facades that own business state and lifecycles. Managers are atomic `Sendable` structs of closures with live, preview and test values. SQLite owns persisted data; sessions never keep copies of it.
- **Concurrency:** Swift 6 language mode. The app and UI/Feature modules default to `MainActor`; Foundation, Models and Services stay nonisolated and say where they hop. No Combine, locks or `DispatchQueue` for new code.
- **Style:** SwiftFormat owns formatting and removes `self` (`mise run ios:format`). One primary type per file, no file header comments, nouns in argument labels. A function that starts by calling its super implementation leaves a blank line after that call (Ertem, 2026-10-20).
- **Comments:** the code explains itself (names, types, small functions). A comment says only what the code can't: a platform quirk or workaround, where a measured constant comes from, a private-API, security or privacy invariant, an ordering or threading rule. One line where it can be; never restate the code, narrate a change, say who decided it or when (that's git and AGENTS.md), or name a reference app. `///` only where a name and its types aren't enough. Every larger change re-checks its own comments (Ertem, 2026-10-19; sweeps: 2026-10-14, 2026-10-19).
- **Logging:** `os.Logger` with explicit privacy. No `print` (lint). Anything a feedback report needs (a recoverable failure) logs at `.notice` or above: `.info` and `.debug` stay in memory, never reach the log store, and so never reach Send Feedback's attached log.
- **Tests:** Swift Testing only. Suites carry `.timeLimit`; no sleeps or yields (lint); compare with CustomDump's `expectNoDifference`; fakes report through `AsyncStream`.
- **Generated code:** never edit `Core/Foundation/APIClientKit/Sources/Generated`; change the backend contract and regenerate.
